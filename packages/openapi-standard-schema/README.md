# @shipworthy/openapi-standard-schema

Generate [Standard Schema](https://standardschema.dev) validators from an OpenAPI document. Each schema in `components.schemas` becomes a pair of named exports: a TypeScript type and a `StandardSchemaV1` validator backed by [Effect](https://effect.website). Any library that accepts Standard Schema can use the validators, including form libraries, tRPC, and TanStack tooling. Use this package when you want runtime validation of OpenAPI component shapes without depending on Zod. It is a generator plugin. Most users run it through the `openapi` CLI (`@shipworthy/openapi-cli`). You can also call it from code on a model produced by `@shipworthy/openapi-transformer`. The sibling `@shipworthy/openapi-zod` generates Zod validators instead.

## Installation

```sh
bun add -d @shipworthy/openapi-standard-schema @shipworthy/openapi-cli
```

The generated file imports `effect`, so your app needs `effect` as a runtime dependency:

```sh
bun add effect@^4.0.0
```

Requirements:

- **Effect 4.** The generated code needs `effect` `^4.0.0`. Effect 3 is not supported.
- **Node.js `>=22.19.0` or Bun.** The package ships compiled JavaScript and `.d.ts` declarations in `dist/`, so no TypeScript loader or bundler is needed. The `openapi` CLI runs on Node.js or Bun (`bunx --bun @shipworthy/openapi-cli ...`).
- **ESM only.** The package sets `"type": "module"` and has a single `.` export. There is no CommonJS build.
- **Installed dependencies.** The package installs `@shipworthy/openapi-generator` and `@shipworthy/openapi-transformer`.

Install `@shipworthy/openapi-cli` only if you use the CLI. For a direct call to `standardSchema.generate`, also install `@shipworthy/openapi-transformer`.

`@shipworthy/openapi-cli` lists this package as an optional peer dependency. It loads the package by name with `import("@shipworthy/openapi-standard-schema")`, so install both.

## Quick start

Run the `openapi` commands below in a package script, or use `bunx --bun @shipworthy/openapi-cli` in place of `openapi`.

`openapi.yaml`:

```yaml
openapi: 3.1.0
info: { title: Pets, version: "1" }
paths: {}
components:
  schemas:
    Pet:
      type: object
      required: [id, name]
      properties:
        id: { type: integer }
        name: { type: string, minLength: 1 }
        tag: { type: [string, "null"] }
```

Generate the validators:

```sh
openapi generate standard-schema -i ./openapi.yaml -o ./src/generated
```

This writes `src/generated/standard-schema.ts`.

Use them:

```ts
import { Pet } from "./generated/standard-schema";

const ok = Pet["~standard"].validate({ id: 1, name: "Rex", tag: null });
// { value: { id: 1, name: "Rex", tag: null } }

const bad = Pet["~standard"].validate({ id: 1.5, name: "" });
// { issues: [
//   { path: ["id"],   message: "Expected an integer" },
//   { path: ["name"], message: "Expected a value with a length of at least 1" },
// ] }

Pet["~standard"].vendor; // "effect"
```

## CLI: `openapi generate standard-schema`

```
openapi generate standard-schema [-i <input>] [-o <dir>] [--camel-case] [--check]
```

| Flag             | Description                                                                                                      |
| ---------------- | ---------------------------------------------------------------------------------------------------------------- |
| `--input`, `-i`  | Path or URL of the OpenAPI document (JSON or YAML). When omitted, the document is read from stdin.               |
| `--output`, `-o` | Output directory. The plugin writes `standard-schema.ts` inside it. When omitted, the code is written to stdout. |
| `--camel-case`   | Rename snake_case property names to camelCase in the exported types and validators. Sets `camelCase: true`.      |
| `--check`        | Write nothing; exit 1 when `standard-schema.ts` in the output directory differs or is missing. Requires `-o`.    |

This plugin does not need `types.ts`. With `-o`, the CLI creates any missing directories, overwrites the file, and logs `<input> → <output>/standard-schema.ts [<elapsed>]`. The output starts with this header:

```ts
/**
 * This file was auto-generated by @shipworthy/openapi-standard-schema.
 * Do not make direct changes to the file.
 *
 * @shipworthy/openapi-standard-schema@<version>:<sha256 of the input document>
 */
```

With `--camel-case`, a `Field casing: camelCase` line follows the stamp, and the hash also covers the casing setting.

A typical `package.json` script:

```json
{
  "scripts": {
    "generate": "openapi generate standard-schema -i openapi.yaml -o src/generated/core"
  }
}
```

The `standard-schema` plugin can be combined with other plugins in one run, for example `openapi generate tanstack-query zod standard-schema -i openapi.yaml -o src/generated/core`. See the [CLI reference](../openapi-cli/README.md#openapi-generate-plugins) for every flag.

## API

The package exports two names from `@shipworthy/openapi-standard-schema`.

### `standardSchema`

```ts
import type { Generator } from "@shipworthy/openapi-generator";

const standardSchema: Generator<string, SchemaGenerationError>;
// {
//   readonly id: "standard-schema";
//   generate(model: ParsedService, options: Readonly<Record<string, unknown>>):
//     Effect.Effect<string, SchemaGenerationError>;
// }
```

- `model` is a `ParsedService` from `@shipworthy/openapi-transformer`.
- `options` is `{ camelCase?: boolean }`. Pass `{}` for the defaults. Unknown keys are ignored. An option of the wrong type fails with `SchemaGenerationError` (`#: Invalid generator options`).
- `camelCase: true` renames lower snake_case property names (`first_name` becomes `firstName`) in every component schema and in top-level `$defs`. The rename covers `properties` keys, `required` entries, `dependentRequired`, and the discriminator `propertyName`, at every depth. The exported types and validators then use camelCase fields. `enum` and `const` values, `patternProperties` keys, and `$ref`s keep the API spelling. Names that are not lower snake_case, such as `_private` or `UPPER_CASE`, are unchanged. If two names at one object level would become the same name, including names merged through `allOf`, `anyOf`, `oneOf`, or a `$ref`, generation fails with `<path>: user_id and userId both become userId`. The default is `false`.
- On success, the Effect yields the TypeScript module source as a string. If the document has no component schemas, the string is empty (`""`).
- On failure, the Effect fails with `SchemaGenerationError`.

#### Through `@shipworthy/openapi-generator`

`generate` loads, bundles, and validates the document. It upgrades OpenAPI 3.0 to 3.1, builds the model, and then runs the plugin. The CLI uses this path.

```ts
import { NodeServices } from "@effect/platform-node";
import { generate, ModuleLoader } from "@shipworthy/openapi-generator";
import { Effect, Layer } from "effect";
import { FetchHttpClient } from "effect/http";
import { writeFile } from "node:fs/promises";
import { pathToFileURL } from "node:url";

const source = await Effect.runPromise(
  generate({
    specifier: "@shipworthy/openapi-standard-schema",
    exportName: "standardSchema",
    source: pathToFileURL("./openapi.yaml"),
  }).pipe(
    Effect.provideService(ModuleLoader, { load: (specifier) => import(specifier) }),
    Effect.provide(Layer.mergeAll(NodeServices.layer, FetchHttpClient.layer)),
  ),
);

await writeFile("./standard-schema.ts", source as string);
```

This example also needs `@effect/platform-node` and `@shipworthy/openapi-generator`. The `ModuleLoader` override resolves the plugin from your script. On Bun, `BunServices` from `@effect/platform-bun` works in place of `NodeServices`.

#### Directly on a model

`decode` from `@shipworthy/openapi-transformer` turns an OpenAPI 3.1 document object into a `ParsedService`. Unlike `generate`, it does not bundle external `$ref`s or upgrade 3.0 documents.

```ts
import { standardSchema } from "@shipworthy/openapi-standard-schema";
import { decode } from "@shipworthy/openapi-transformer";
import { Effect } from "effect";

const program = Effect.gen(function* () {
  const model = yield* decode({
    openapi: "3.1.0",
    info: { title: "Pets", version: "1" },
    paths: {},
    components: {
      schemas: {
        Pet: {
          type: "object",
          required: ["id", "name"],
          properties: { id: { type: "integer" }, name: { type: "string", minLength: 1 } },
        },
      },
    },
  });

  return yield* standardSchema.generate(model, {});
});

const source = await Effect.runPromise(program);
```

### `SchemaGenerationError`

```ts
class SchemaGenerationError extends Schema.TaggedError<SchemaGenerationError>()(
  "SchemaGenerationError",
  { message: Schema.String, cause: Schema.optionalKey(Schema.Defect()) },
) {}
```

`standardSchema.generate` raises this error for invalid options, for a camelCase name collision, when a component schema is neither an object nor a boolean, and when Effect cannot convert or render a schema. In the second case, `message` is copied from the underlying error and `cause` holds that error. Handle it with `Effect.catchTag("SchemaGenerationError", …)`. When the plugin runs through `@shipworthy/openapi-generator`'s `generate`, the error is wrapped in a `TransformError` that has the same `message`.

## Generated output

For each component `Name`, the generated module exports a TypeScript type named `Name` and a
Standard Schema validator with the same name. Import the validator to check values and the
type to annotate application data.

Validation is synchronous: `~standard.validate` returns a result rather than a Promise.
Success returns `{ value }`; failure returns `{ issues }`, with a path and message for each
issue.

Generated validators enforce supported source constraints, including enum values, patterns,
string lengths, integer requirements, numeric bounds, required properties, nullable values,
and additional-property rules. Recursive component references are supported. Schema `false`
rejects every value. Component and property names are preserved, including when local
`$defs` entries reuse a component name.

References inside literal `examples`, `default`, `const`, and `enum` values are preserved as data. Only references in schema positions are rewritten for generated validators.

## Supported OpenAPI versions

The CLI and `@shipworthy/openapi-generator` accept OpenAPI `3.0.x` and `3.1.x`. 3.0 documents are upgraded to 3.1 (JSON Schema Draft 2020-12) before generation. Swagger 2.0 is rejected. `standardSchema.generate` itself expects a `ParsedService` in the 3.1 dialect.

## Limitations

- Only `components.schemas` is emitted. The generator does not produce validators for request bodies, responses, parameters, or headers. Generate a component for any payload you want to validate.
- An empty `components.schemas` gives an empty output string, not a module with zero exports.
- Validators are not wired into any HTTP client. Call them where a payload should be checked.
- Objects accept extra JSON-valued properties unless the schema sets `additionalProperties: false`.
- The only generator option is `camelCase`.

## Troubleshooting

- **`Install @shipworthy/openapi-standard-schema to load standardSchema.`** (`MissingPlugin`): the CLI could not import this package. Install it in the same project as `@shipworthy/openapi-cli`.
- **`Cannot find module 'effect'` when importing the generated file**: install `effect` (`^4.0.0`) as a runtime dependency.
- **`<path>: expected a JSON schema`** (`SchemaGenerationError`): the component schema at `<path>` is not an object or boolean.
- **Empty output file**: the document has no `components.schemas`.

## Key facts (for AI agents)

- Package: `@shipworthy/openapi-standard-schema`, ESM-only compiled JavaScript with `.d.ts` declarations. Node.js `>=22.19.0` or Bun. Depends on `effect@^4`. Exports: `standardSchema` (generator plugin, `id: "standard-schema"`) and `SchemaGenerationError`.
- CLI: `openapi generate standard-schema [-i <input>] [-o <dir>] [--camel-case]` (from `@shipworthy/openapi-cli`, runs on Node.js or Bun) writes `<dir>/standard-schema.ts`. Without `-i`, it reads stdin; without `-o`, output goes to stdout. It can run in one command with other plugins.
- `standardSchema.generate(model: ParsedService, { camelCase?: boolean })` returns `Effect<string, SchemaGenerationError>`. The string is a TS module, or `""` when there are no component schemas.
- Output: for each `components.schemas` entry `Name`, `export type Name` and `export const Name = Schema.toStandardSchemaV1(...)`. Validate with `Name["~standard"].validate(value)`, which is synchronous and returns `{ value }` or `{ issues }`. `vendor` is `"effect"`.
- The generated code needs `effect` (`^4.0.0`) at runtime.
- Input: OpenAPI 3.0/3.1 through the CLI or `@shipworthy/openapi-generator`. 3.0 is upgraded to 3.1.
- Not generated: request bodies, responses, parameters. Validators are standalone and are not called by a fetch client.
- Do not edit generated files. Re-run the CLI instead.
