# @shipworthy/openapi-standard-schema

Generate [Standard Schema](https://standardschema.dev) validators from an OpenAPI document. Each schema in `components.schemas` becomes a pair of named exports: a TypeScript type and a `StandardSchemaV1` validator built with [Effect Schema](https://effect.website) (`Schema.toStandardSchemaV1`). Any library that accepts Standard Schema can use the validators, including form libraries, tRPC, and TanStack tooling. Use this package when you want runtime validation of OpenAPI component shapes without depending on Zod. It is a generator plugin. Most users run it through the `openapi` CLI (`@shipworthy/openapi-cli`). You can also call it from code on a model produced by `@shipworthy/openapi-transformer`. The sibling `@shipworthy/openapi-zod` generates Zod validators instead.

## Installation

```sh
npm install -D @shipworthy/openapi-standard-schema @shipworthy/openapi-cli
pnpm add -D @shipworthy/openapi-standard-schema @shipworthy/openapi-cli
yarn add -D @shipworthy/openapi-standard-schema @shipworthy/openapi-cli
bun add -d @shipworthy/openapi-standard-schema @shipworthy/openapi-cli
```

The generated file imports `effect`, and the package lists it as a peer dependency, so your app needs `effect` as a runtime dependency:

```sh
npm install effect@^4.0.0
pnpm add effect@^4.0.0
yarn add effect@^4.0.0
bun add effect@^4.0.0
```

Requirements:

- **Effect 4.** `effect` `^4.0.0` is a peer dependency, so every package shares one Effect instance. The generated code uses Effect 4 Schema APIs (`Schema.toStandardSchemaV1`, `Schema.StructWithRest`, `Schema.isPattern`, and others). Effect 3 will not run it.
- **Node.js `>=22.19.0` or Bun.** The package ships compiled JavaScript and `.d.ts` declarations in `dist/`, so no TypeScript loader or bundler is needed. The `openapi` CLI runs on Node.js (`npx @shipworthy/openapi-cli ...`) or Bun (`bunx --bun @shipworthy/openapi-cli ...`).
- **ESM only.** The package sets `"type": "module"` and has a single `.` export. There is no CommonJS build.
- **Installed dependencies.** The package installs `@shipworthy/openapi-generator` and `@shipworthy/openapi-transformer`.

Install `@shipworthy/openapi-cli` only if you use the CLI. For a direct call to `standardSchema.generate`, also install `@shipworthy/openapi-transformer`.

`@shipworthy/openapi-cli` lists this package as an optional peer dependency. It loads the package by name with `import("@shipworthy/openapi-standard-schema")`, so install both.

## Quick start

Run the `openapi` commands below in a package script, or use `npx @shipworthy/openapi-cli` (Node.js) or `bunx --bun @shipworthy/openapi-cli` (Bun) in place of `openapi`.

`openapi.yaml`:

```yaml
openapi: 3.1.0
info: { title: Pets, version: "1" }
paths: {}
components:
  schemas:
    Pet:
      type: object
      required: [id, name]
      properties:
        id: { type: integer }
        name: { type: string, minLength: 1 }
        tag: { type: [string, "null"] }
```

Generate the validators:

```sh
openapi generate standard-schema ./openapi.yaml -o ./src/generated/standard-schema.ts
```

Use them:

```ts
import { Pet } from "./generated/standard-schema";

const ok = Pet["~standard"].validate({ id: 1, name: "Rex", tag: null });
// { value: { id: 1, name: "Rex", tag: null } }

const bad = Pet["~standard"].validate({ id: 1.5, name: "" });
// { issues: [
//   { path: ["id"],   message: "Expected an integer" },
//   { path: ["name"], message: "Expected a value with a length of at least 1" },
// ] }

Pet["~standard"].vendor; // "effect"
```

## CLI: `openapi generate standard-schema`

```
openapi generate standard-schema [flags] <input>
```

| Argument / flag  | Description                                                   |
| ---------------- | ------------------------------------------------------------- |
| `<input>`        | Required. Path or URL of the OpenAPI document (JSON or YAML). |
| `--output`, `-o` | Output file. When omitted, the code is written to stdout.     |

With `-o`, the CLI creates any missing parent directories, overwrites the file, and logs `<input> → <output> [<elapsed>]`. The output starts with this header:

```ts
/**
 * This file was auto-generated by @shipworthy/openapi-standard-schema.
 * Do not make direct changes to the file.
 *
 * @shipworthy/openapi-standard-schema@<version>:<sha256 of the input document>
 */
```

The example SDKs in this repository run it as a `generate` script:

```json
{
  "scripts": {
    "generate": "openapi generate standard-schema openapi.yaml -o src/generated/core/standard-schema.ts"
  }
}
```

## API

The package exports two names from `@shipworthy/openapi-standard-schema`.

### `standardSchema`

```ts
import type { Generator } from "@shipworthy/openapi-generator";

const standardSchema: Generator<string, SchemaGenerationError>;
// {
//   readonly id: "standard-schema";
//   generate(model: ParsedService, options: Readonly<Record<string, unknown>>):
//     Effect.Effect<string, SchemaGenerationError>;
// }
```

- `model` is a `ParsedService` from `@shipworthy/openapi-transformer`.
- `options` is accepted for compatibility with the `Generator` interface. This generator reads no options, so pass `{}`.
- On success, the Effect yields the TypeScript module source as a string. If the document has no component schemas, the string is empty (`""`).
- On failure, the Effect fails with `SchemaGenerationError`.

#### Through `@shipworthy/openapi-generator`

`generate` loads, bundles, and validates the document. It upgrades OpenAPI 3.0 to 3.1, builds the model, and then runs the plugin. The CLI uses this path.

```ts
import { NodeServices } from "@effect/platform-node";
import { generate, ModuleLoader } from "@shipworthy/openapi-generator";
import { Effect, Layer } from "effect";
import { FetchHttpClient } from "effect/http";
import { writeFile } from "node:fs/promises";
import { pathToFileURL } from "node:url";

const source = await Effect.runPromise(
  generate({
    specifier: "@shipworthy/openapi-standard-schema",
    exportName: "standardSchema",
    source: pathToFileURL("./openapi.yaml"),
  }).pipe(
    Effect.provideService(ModuleLoader, { load: (specifier) => import(specifier) }),
    Effect.provide(Layer.mergeAll(NodeServices.layer, FetchHttpClient.layer)),
  ),
);

await writeFile("./standard-schema.ts", source as string);
```

This example also needs `@effect/platform-node` and `@shipworthy/openapi-generator`. The `ModuleLoader` override resolves the plugin from your script. On Bun, `BunServices` from `@effect/platform-bun` works in place of `NodeServices`.

#### Directly on a model

`decode` from `@shipworthy/openapi-transformer` turns an OpenAPI 3.1 document object into a `ParsedService`. Unlike `generate`, it does not bundle external `$ref`s or upgrade 3.0 documents.

```ts
import { standardSchema } from "@shipworthy/openapi-standard-schema";
import { decode } from "@shipworthy/openapi-transformer";
import { Effect } from "effect";

const program = Effect.gen(function* () {
  const model = yield* decode({
    openapi: "3.1.0",
    info: { title: "Pets", version: "1" },
    paths: {},
    components: {
      schemas: {
        Pet: {
          type: "object",
          required: ["id", "name"],
          properties: { id: { type: "integer" }, name: { type: "string", minLength: 1 } },
        },
      },
    },
  });

  return yield* standardSchema.generate(model, {});
});

const source = await Effect.runPromise(program);
```

### `SchemaGenerationError`

```ts
class SchemaGenerationError extends Schema.TaggedError<SchemaGenerationError>()(
  "SchemaGenerationError",
  { message: Schema.String, cause: Schema.optionalKey(Schema.Defect()) },
) {}
```

`standardSchema.generate` raises this error when a component schema is neither an object nor a boolean, and when Effect cannot convert or render a schema. In the second case, `message` is copied from the underlying error and `cause` holds that error. Handle it with `Effect.catchTag("SchemaGenerationError", …)`. When the plugin runs through `@shipworthy/openapi-generator`'s `generate`, the error is wrapped in a `TransformError` that has the same `message`.

## Generated output

For each component `Name`, in document order, the generated file exports:

```ts
export type Name = NameSchema; // TypeScript type of the decoded value
export const Name = Schema.toStandardSchemaV1(NameSchema); // StandardSchemaV1 validator
```

The file also contains these parts:

- `import { Schema } from "effect";`, plus any other imports that Effect's code generator emits.
- A module-private `type XSchema` and `const XSchema` (an Effect `Schema`) for each component and each shared `$defs` entry. Each component's internal binding is `<Name>Schema`. If that name is taken, the generator appends more `Schema` suffixes.
- `Schema.suspend((): Schema.Codec<XSchema> => …)` declarations for recursive and mutually recursive schemas. The private bodies of these schemas are named `__recursive_<Name>`.

Validation is synchronous: `~standard.validate` returns a result, not a Promise. A successful result is `{ value }`. A failed result is `{ issues }`, and each issue has a `path` and a `message`.

Observed conversions (from tests and sample output):

| OpenAPI / JSON Schema                             | Effect Schema                                                                                           |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `type: [string, "null"]`, or 3.0 `nullable: true` | `Schema.Union([Schema.String, Schema.Null])`                                                            |
| `enum: [a, b]`                                    | `Schema.Literals(["a", "b"])`                                                                           |
| `pattern: "^a+$"`                                 | `.check(Schema.isPattern(new RegExp("^a+$", "u")))` (enforced)                                          |
| `minLength`, `type: integer`, `minimum`           | `.check(Schema.isMinLength(…))`, `Schema.isInt()`, `Schema.isGreaterThanOrEqualTo(…)`                   |
| Property not listed in `required`                 | `Schema.optionalKey(…)` (`readonly "x"?: T`)                                                            |
| `object` without `additionalProperties: false`    | `Schema.StructWithRest(…, [Schema.Record(Schema.String, Schema.Json)])`, so extra JSON keys are allowed |
| `object` with `additionalProperties: false`       | `Schema.Struct(…)`                                                                                      |
| `$ref: "#/components/schemas/X"`                  | A reference to `XSchema`                                                                                |
| Schema `false`                                    | `Schema.Never` (rejects every value)                                                                    |
| `description`, `examples`                         | Kept as `.annotate({ … })`                                                                              |

Name collisions are handled:

- A property whose name matches the component it references (for example, `Account.properties.User → User`) keeps its key: `"User": Schema.optionalKey(UserSchema)`.
- A schema-local `$defs` entry that shares a name with a component does not replace that component.
- A document-level `$defs` entry that shares a name with a component is renamed internally (`Name_2`, …), and both schemas are kept.

## Supported OpenAPI versions

The CLI and `@shipworthy/openapi-generator` accept OpenAPI `3.0.x` and `3.1.x`. 3.0 documents are upgraded to 3.1 (JSON Schema Draft 2020-12) before generation. Swagger 2.0 is rejected. `standardSchema.generate` itself expects a `ParsedService` in the 3.1 dialect.

## Limitations

- Only `components.schemas` is emitted. The generator does not produce validators for request bodies, responses, parameters, or headers. Generate a component for any payload you want to validate.
- An empty `components.schemas` gives an empty output string, not a module with zero exports.
- Validators are not wired into any HTTP client. Call them where a payload should be checked.
- Objects accept extra JSON-valued properties unless the schema sets `additionalProperties: false`.
- The generator has no options.

## Troubleshooting

- **`Install @shipworthy/openapi-standard-schema to load standardSchema.`** (`MissingPlugin`): the CLI could not import this package. Install it in the same project as `@shipworthy/openapi-cli`.
- **`Cannot find module 'effect'` when importing the generated file**: install `effect` (`^4.0.0`) as a runtime dependency.
- **`<path>: expected a JSON schema`** (`SchemaGenerationError`): the component schema at `<path>` is not an object or boolean.
- **Empty output file**: the document has no `components.schemas`.

## Key facts (for AI agents)

- Package: `@shipworthy/openapi-standard-schema`, ESM-only compiled JavaScript with `.d.ts` declarations. Node.js `>=22.19.0` or Bun. Peer dependency `effect@^4`. Exports: `standardSchema` (generator plugin, `id: "standard-schema"`) and `SchemaGenerationError`.
- CLI: `openapi generate standard-schema <input> [-o <file>]` (from `@shipworthy/openapi-cli`, runs on Node.js or Bun). Without `-o`, output goes to stdout.
- `standardSchema.generate(model: ParsedService, {})` returns `Effect<string, SchemaGenerationError>`. The string is a TS module, or `""` when there are no component schemas.
- Output: for each `components.schemas` entry `Name`, `export type Name` and `export const Name = Schema.toStandardSchemaV1(...)`. Validate with `Name["~standard"].validate(value)`, which is synchronous and returns `{ value }` or `{ issues }`. `vendor` is `"effect"`.
- The generated code needs `effect` (`^4.0.0`) at runtime.
- Input: OpenAPI 3.0/3.1 through the CLI or `@shipworthy/openapi-generator`. 3.0 is upgraded to 3.1.
- Not generated: request bodies, responses, parameters. Validators are standalone and are not called by a fetch client.
- Do not edit generated files. Re-run the CLI instead.
